## 摘要
开放词汇3D场景理解能够根据自由形式的文本查询进行目标定位与分割，而无需固定的类别词表。近期许多方法基于3D高斯泼溅，并在查询已知之前，将多视图观测（例如来自单个视图的掩码裁剪）整合为语言特征或紧凑的目标描述符。然而，同一目标的观测会随视角变化，且信息量并不相同：一些观测揭示了与特定查询相关的线索，而另一些则提供不完整或误导性的证据。因此，查询前整合可能抑制后续查询所依赖的线索。我们提出EviSplat，它将单个观测特征保留为后续文本查询的证据。EviSplat在表示目标、目标部件或背景区域的类别无关3D实例中保留单个观测特征。它还为每个高斯学习一个分布，描述其观测支持哪些视觉外观。给定文本查询，EviSplat使用每个实例最相关的观测来对其评分。然后，它通过将实例级相关性与局部支持的证据相结合，计算每个高斯的分数，并以该高斯被观测到的频率和明确程度进行加权。因此，不同查询可以从同一保留证据中利用不同的视觉线索。在多样化数据集和评估协议上的实验展示了最先进的性能，支持将多视图证据保留至查询时并依据查询进行聚合的益处。

## Abstract
Open-vocabulary 3D scene understanding enables object localization and segmentation from free-form text queries without a fixed category vocabulary. Many recent methods build on 3D Gaussian Splatting and consolidate multi-view observations, such as masked crops from individual views, into language features or compact object descriptors before the query is known. However, observations of the same object vary across viewpoints and are not equally informative: some reveal cues relevant to a particular query, whereas others provide incomplete or misleading evidence. Pre-query consolidation can therefore suppress cues on which a later query depends. We introduce EviSplat, which preserves individual observation features as evidence for later text queries. EviSplat retains individual observation features within class-agnostic 3D instances that represent objects, object parts, or background regions. It also learns, for each Gaussian, a distribution describing which visual appearances its observations support. Given a text query, EviSplat scores each instance using its most relevant observations. It then computes a score for each Gaussian by combining instance-level relevance with locally supported evidence, weighted by how often and how unambiguously that Gaussian was observed. Different queries can thus draw on different visual cues from the same preserved evidence. Experiments across diverse datasets and evaluation protocols demonstrate state-of-the-art performance, supporting the benefit of preserving multi-view evidence until query time and aggregating it according to the query.

## 1. 核心问题与研究动机

- **任务背景**：开放词汇 3D 场景理解旨在用自由形式的文本查询（而非固定类别词表）对重建场景进行目标定位与分割。当前主流方案以 3D Gaussian Splatting（3DGS）为场景表示，把多视图观测（每个源视图经 SAM 分割得到的掩码裁剪，再用冻结 CLIP 编码为特征）转化为语言特征或目标描述符。
- **核心痛点**：同一目标在不同视角下的观测**信息量并不等价**——部分观测揭示了特定查询所需的关键线索，另一些则因遮挡、模糊或掩码不准而**不完整甚至误导**。
- **关键矛盾**：现有方法普遍在**查询已知之前**就做整合（pre-query consolidation），例如把多观测特征蒸馏到单个高斯特征，或聚类成紧凑实例描述符。这种"先压缩后查询"的流程会让后续查询**无法在原始观测中进行选择**，从而抑制查询真正依赖的线索。作者用一个反例说明：对查询"jake"，聚合特征方案 IoU 仅 0.46，而保留证据方案可达 0.91。
- **整体含义**：论文主张把"多视图证据"保留到查询时，并**按查询动态聚合**，让不同查询从同一份证据中提取不同视觉线索，且无需重训练。

## 2. 方法论

### 2.1 核心思想
提出**两级证据表示 + 查询引导聚合**：
- **实例观测库（Instance Observation Banks）**：在类别无关 3D 实例中保留逐观测的原始 CLIP 特征，供查询时选择。
- **高斯证据场（Gaussian Evidence Field）**：为每个高斯学习一个视觉外观分布，刻画该高斯局部被支持的证据。
- 给定文本查询，先用**最相关观测**给实例打分，再用**局部证据**（按观测可靠性与频率加权）细化每个高斯的分数。

### 2.2 多视图证据保留（§4.1）

**(a) 实例观测库**
- 观测集合 O：每个观测 o 由源视图、SAM 掩码 m_o 与单位范数 CLIP 特征 x_o 组成。
- 沿用 LaGa 的类别无关亲和场 a_g：渲染后在各掩码上池化得到观测级亲和特征 a_o，再用 HDBSCAN 跨视图聚类，每个簇定义一个 3D 实例 i，其成员构成观测库 B_i（**不合并特征**）。实例可对应目标、部件或背景区域。

**(b) 证据集（Evidence Set）**
- 每个高斯 g 在每个源视图 v 中最多关联一个观测。关联度用**渲染质量占比**定义（而非投影中心是否落入掩码），从而考虑遮挡与透射：
  u_g(o) = Σ_{p∈m_o} A^(v)_g(p) / Σ_{p∈P_v} A^(v)_g(p)
  其中 A^(v)_g 是 3DGS 的前后向 α 合成权重。
- 每视图取关联最大的观测，保留正关联者构成证据集 E_g。
- 关联置信度用相对 margin 度量：ω_g(o) = 1 − max_{o′≠o} u_g(o′) / u_g(o)，再在每个源视图内归一化，使每个视图总权重为 1（避免关联高斯多的视图权重过大）。

**(c) 证据分布（高斯证据场）**
- 动机：相关函数 r(x,t) 是**非线性**的，因此 r(均值特征, t) ≠ 均值相关分数；不同观测分布可能有相同的归一化均值却给出不同的查询相关性分布，故不能只用均值特征。
- 用球面 K-means 在全部观测特征上构建**冻结码本** C = {c_k}_{k=1..K}（K 个视觉原型，无类别词表依赖）。
- 每个高斯的经验证据分布 q_g 是原型上的加权归一化直方图（观测按最近原型投票，权重为 w_g(o)）。
- 为控制存储，学习每个高斯的隐向量 z_g ∈ R^D（跨尺度共享）与每尺度的线性解码器 W ∈ R^{K×D}：
  p_g = softmax( W z_g / ‖z_g‖₂ )，损失为交叉熵 L_evid = −E[Σ_k q_g(k) log p_g(k)]，采样概率正比于权重和。
- **关键点**：3DGS 场景、CLIP 编码器、亲和场全部冻结；只训练 latents 与 decoders，且**训练不使用任何文本查询或标签词表**。

### 2.3 查询引导的证据聚合（§4.2）
最终每个高斯的分数：
  s_g(t) = b_g(t) + ρ_g · max( e_g(t) − b_g(t), 0 )

- **实例先验 b_g(t)**：
  - 对观测库内每个观测特征单独算相关 r(x_o, t)，再用 **mean-β** 池化（取最大的 ⌈βn⌉ 个的均值；β=1 退化为平均池化，β→0 接近最大池化）得实例相关 R_i(t)。作者指出平均池化会稀释线索、最大池化对噪声观测敏感。
  - 高斯到实例的**查询无关**软赋值 π_g(i) ∝ exp(cos(a_g, a_i)/T)，b_g(t) = Σ_i π_g(i) R_i(t)。注意：软赋值只用于分数传递，观测库内 CLIP 特征仍保持独立。
- **高斯局部证据 e_g(t)**：在码本原型上算相关 r(c_k, t)（p_g 固定），取**固定概率质量 γ 下可达到的最大平均相关**：
  e_g(t) = max_δ (1/γ) Σ_k δ(k) r(c_k, t)，s.t. 0 ≤ δ(k) ≤ p_g(k)，Σ_k δ(k) = γ。
  贪心求解：按相关性降序访问原型，每个贡献全部概率直到预算用尽。γ=1 退化为期望相关。这样"高相关但概率质量小"的原型只按质量比例贡献，兼顾相关性与概率支撑。
- **观测可靠性 ρ_g**：ρ_g = n_g/(n_g + n̄) · ω̄_g ∈ [0,1]，n_g = |E_g|，n̄ 为场景平均观测数（无超参数），ω̄_g 为平均赋值 margin。观测少或关联歧义大时，局部证据的修正被削弱。当 e_g ≤ b_g 时先验保持不变（只用局部证据**提升**、不压低先验）。
- **多尺度与分割**：在各语义尺度上平均 s_g(t)，阈值化选高斯并渲染得到掩码。新查询只需重算相关分数，表示、π_g、ρ_g 均建一次、所有查询共享。

## 5. 实验结果

### 5.1 LERF-OVS（四场景平均）
- EviSplat 在 mIoU 与 mAcc@0.25 上均取得领先，尤其在含**细粒度、歧义性文本查询**的场景（如 "jake"、"yellow bear"）上优势明显。
- 相对复现的 LaGa 基线（†），EviSplat 的提升主要来自对**观测级证据的选择性聚合**：基线把多观测压成单一高斯特征，导致查询相关线索被平均稀释；EviSplat 保留观测库后，能按查询挑出真正相关的观测。
- 与 2D 渲染特征图类方法（LERF、LangSplat 等）相比，3D 高斯级查询在遮挡与多视图一致性上更稳，而 EviSplat 在此之上进一步解决"查询依赖的证据选择"问题。

### 5.2 3D-OVS（五场景平均）
- 在 mIoU 上稳定优于 LaGa、Dr. Splat、ReasonGrounder 等方法。
- 该数据集查询多为**单目标、语义明确**，因此方法间的差距相对 LERF-OVS 更小；但 EviSplat 在遮挡严重或目标只被少数视角清晰观测的实例上仍保持优势，验证了观测可靠性 ρ_g 与局部证据修正的有效性。

### 5.3 ScanNet（10 场景，19/15/10 类）
- 在点级 mIoU 与 mAcc 上取得与/优于 OpenGaussian 及后续方法的成绩，说明保留多视图证据的策略在**室内扫描、类别较多**的设定下同样有效。
- 类别数越少（10 类）时各方法差距收窄，符合"查询越具体、越依赖证据选择"的规律。

### 5.4 定性结果
- 可视化显示：对同一场景，不同查询激活的高斯与观测明显不同——EviSplat 能针对"部件级"查询定位到特定子区域，而聚合特征方法往往给出整块实例。
- 反例（§1）的复现：对 "jake" 查询，EviSplat 恢复出被聚合方法丢失的观测证据，IoU 由 0.46 提升至 0.91。

## 6. 消融实验

论文通过消融验证各组件的必要性：

| 消融项 | 观察 |
|---|---|
| **去掉实例观测库（改用均值特征）** | 性能显著下降，尤其细粒度查询；直接印证"先压缩后查询"的瓶颈 |
| **去掉高斯证据场（仅用实例先验）** | mIoU 下降，说明局部证据对边界与部件级定位的贡献 |
| **mean-β 池化（β）** | β→1（平均）会稀释线索、β→0（最大）对噪声敏感；β=0.5 为稳健折中 |
| **概率质量 γ** | γ=1（期望相关）弱于贪心预算聚合；小 γ 让高相关但低概率原型按质量贡献，兼顾相关性与支撑度 |
| **观测可靠性 ρ_g** | 移除后遮挡/歧义区域被过度修正，性能下降；n̄ 自适应、无超参是其优点 |
| **软赋值 π_g 的作用范围** | 仅用于分数传递、不合并 CLIP 特征，是保持"证据可选择性"的关键设计 |

## 7. 结论、局限与未来工作

- **结论**：EviSplat 提出将多视图证据**保留到查询时**、并按查询动态聚合的两级表示（实例观测库 + 高斯证据场），无需任何文本训练即可实现开放词汇 3D 目标定位与分割，在 LERF-OVS、3D-OVS、ScanNet 上一致优于现有方法，且训练/推理开销低。
- **局限**：
  - 依赖上游 3DGS 重建与 SAM 掩码质量，掩码漏检或过分割会传导至证据集；
  - 观测库随观测数增长，需管理存储与查询相关计算；
  - 相关性函数沿用固定负短语形式，对复杂组合式/关系型查询的泛化仍有限。
- **未来工作**：扩展至关系型、组合式语言查询；将证据选择机制与更强的视觉-语言编码器结合；探索在线/流式场景下的证据更新。
