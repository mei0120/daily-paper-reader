## 摘要
开放词汇三维场景建图旨在构建环境中物体的持久表示。现有系统通常依赖人工设计的建图流程来关联观测、跨视图融合信息，并在时间上维持一致的场景表示。许多系统还会存储特征丰富的物体表示，例如嵌入或图像裁剪，这增加了持久记忆的规模和复杂度。我们提出 SceneLM，一种场景-语言模型，直接维护文本场景地图。整个场景被表示为一个结构化的物体文本列表，并作为模型唯一的持久记忆。对于每张输入图像，模型读取当前场景状态，并通过添加、编辑和删除物体来更新地图。为学习这一行为，我们引入用于迭代式场景地图维护的监督任务，以及一个无需人工标注即可从图像生成训练数据的自动标注流程。我们在语言引导的检索基准和定位基准上评估 SceneLM。在两个基准上，该模型生成的场景地图与由专用感知和几何模块构建的完整建图系统相比具有竞争力，同时生成的场景表示紧凑 6–12 倍。我们进一步通过在四足机器人上的实验表明，SceneLM 可以在边缘设备上在线运行。这些结果表明，持久开放词汇三维场景地图可以直接由单个视觉-语言模型仅使用轻量级文本表示来维护。训练与推理代码见 https://goldengait.github.io/scenelm/。

## Abstract
Open-vocabulary 3D scene mapping aims to build a persistent representation of the objects in an environment. Existing systems typically rely on engineered mapping pipelines to associate observations, merge information across views, and maintain a consistent scene representation over time. Many additionally store feature-rich object representations, such as embeddings or image crops, increasing the size and complexity of the persistent memory. We introduce SceneLM, a Scene-Language Model that directly maintains a textual scene map. The full scene is represented as a structured text list of objects, which serves as the model's only persistent memory. For each input image, the model reads the current scene state and updates the map by adding, editing, and removing objects. To learn this behavior, we introduce supervision tasks for iterative scene map maintenance together with an automatic annotation pipeline that generates training data from images without human labels. We evaluate SceneLM on both a language-grounded retrieval benchmark and a localization benchmark. Across both benchmarks, the model produces a scene map that achieves competitive performance with complete mapping systems built from dedicated perception and geometric modules while producing a scene representation that is 6-12x more compact. We further show that SceneLM can be run online on an edge device through experiments on a quadruped. These results show that a persistent open-vocabulary 3D scene map can be maintained directly by a single vision-language model using only a lightweight text representation. Training and inference code is available on https://goldengait.github.io/scenelm/.

  - 许多系统额外存储**特征丰富的物体表示**（视觉嵌入、图像裁剪、分割掩码），导致持久记忆越来越大、系统越来越复杂。
- **核心问题**：能否**不依赖专用建图后端**，而是让**单个视觉-语言模型（VLM）仅用轻量文本表示作为持久记忆**，自己学会场景地图的维护（发现、关联、纠错、删除）？
- **整体含义**：论文提出 SceneLM，将"场景地图维护"这一通常由显式几何/关联模块完成的任务，转化为一个**自回归的语言建模问题**，支持开放词汇查询、检索与导航定位，并能在边缘设备上在线运行。其更大意义在于：未来的 VLM 可能"吸收"当前由专用建图组件承担的持久场景状态维护能力。

## 2. 方法论

### 核心思想
- 将**完整场景表示为一个结构化的物体文本列表**（类别标签、短描述、3D 世界坐标），这是模型的**唯一持久记忆**（不保留视觉嵌入、图像裁剪或特征库）。
- 场景维护建模为自回归过程：$M_t = f_\theta(M_{t-1}, I_t)$，其中 $I_t$ 是带位姿的 RGB-D 观测。
- 每个时间步，模型预测三类操作来更新地图：
  - **ADD**：插入新物体；
  - **EDIT**：更新已有条目的标签、描述或位置；
  - **REMOVE**：删除错误或冗余条目。
- 这些操作在**单次前向传播**中联合完成跨视图关联与地图一致性维护，无需外部跟踪、优化或几何数据关联。

### 关键技术细节
- **可见性过滤**：用相机位姿和深度筛选 $M_{t-1}$ 中当前帧可见的物体，序列化为结构化文本，与 RGB 图像一起送入模型。
- **定位方式**：预测物体用归一化 [0,1000] 图像坐标下的 **2D 锚点**表示，通过深度和相机位姿反投影到 3D。
- **训练目标构造**：OVAL 只提供单帧物体标注，不提供地图转移；因此算法化地构造"输入场景地图上下文 + 图像 + 更新操作"的训练样本。

### OVAL 自动标注流程（数据来源）
1. **物体提议**：稀疏开放词汇检测器（YOLOE）或稠密可提示分割器（SAM），稠密变体迭代采样未覆盖区域，覆盖率更高。每个提议只保留**最内部掩码像素**作为 2D 锚点。
2. **物体描述**：掩码条件化的描述模型（DescribeAnything）生成长描述，再由 Qwen3 压缩为名词短语 + 短描述。
3. **质量过滤**：Qwen3-VL-30B 对每个标注做相关性/一致性判断，输出接受/拒绝及理由；被拒标注保留为结构化负样本，用于 REMOVE 训练。
4. **辅助训练数据（腐蚀池）**：构造三类腐蚀——语义不同的视觉相似硬负样本、同义词变体、随机干扰项，用于监督 EDIT 和 REMOVE。

### 训练任务设计
- **ADD 任务**：
  - 无上下文（空地图，预测所有可见物体，学习初始建图）；
  - 部分上下文（给定部分物体，只添加缺失的，避免重复/重复引入），通过空间裁剪或随机子采样生成，增强对不完整地图的鲁棒性和跨视图关联能力。
- **EDIT-REMOVE 任务**：给定被腐蚀的地图（错误标签、扰动位置、重复条目、幻觉物体），预测稀疏的 EDIT/REMOVE 操作；未提及的物体默认保留，允许空更新脚本。
  - **关键设计**：不采用"每张图一个腐蚀率"（会导致图像级相关性、退化为"全改/全不改"策略），而是**对每个物体独立腐蚀**（概率 $q \sim U[0.05, 0.20]$），迫使模型基于视觉证据做物体级决策。
- **避免操作歧义**：扰动幅度占据互不重叠的锚点空间范围——无操作抖动（约 1% 画面）、编辑位移（1.5–10%）、删除位移（≥30%）。
- **序列化防作弊**：场景地图条目按空间顺序序列化，插入腐蚀后重新排序，防止模型利用列表位置识别被编辑或幻觉的物体。

### 训练配置
- 基座模型：Qwen3-VL-2B/4B-Instruct；**全量微调**视觉编码器 + 投影器 + 语言模型。
- AdamW，余弦调度（warmup 0.05），峰值学习率 $2\times10^{-5}$，权重衰减 0.05，3 个 epoch，有效 batch size 128，序列长度 4096，bf16 精度，DeepSpeed ZeRO-2。
- 任务混合：ADD 与 EDIT-REMOVE 以 0.7/0.3 采样；EDIT-REMOVE 中 40% 为空操作样本；ADD 中一半提供部分场景地图。

## 6. 主要结论与发现

- **单帧能力**：微调后 SceneLM 消除了现成 VLM 的循环重复（loop 从 20–40% 降至 0），EDIT-REMOVE 决策 F1 从约 30% 提升到 60% 以上，误触率从 83–91% 降至 10–25%，REMOVE 召回从近乎为零显著提升；被正确动作分类的编辑中，标签纠正率 81–87%，位置改善率 77–78%。
- **检索**：SceneLM 在 ScanNet 与 HM3D 上提升 R@5、R@10 与 MRR，Acc@1 与 FARM 相当或更好；短描述主要提升检索；去掉 EDIT-REMOVE 训练退化最大（尤其 ScanNet）。
- **定位**：Matterport3D 上在所有距离阈值下精度均超过 OpenScene/OpenMask3D/TagMap，0.1 m 与 0.5 m 增益最大；Dense 提议提升召回，Sparse 提议精度最高。
- **关键组件结论**：
  - 提议源决定"覆盖度-精度"工作点（持久建图中覆盖度更重要，因为漏掉的物体可能不再被观测到，而虚假条目可后续纠正）；
  - 短描述帮助物体身份区分（对单帧定位影响小）；
  - EDIT-REMOVE 训练对保持地图一致性至关重要；
  - 质量过滤主要提升精度；排序与坐标量化影响较小。
- **效率**：场景内存比 FARM 小 6–12 倍（ScanNet 3.5 MiB vs 23 MiB；HM3D 10.8 MiB vs 125 MiB），但每帧延迟约 3 倍（约 900 ms vs 约 260 ms）。
- **部署**：2B NVFP4 量化模型可在 Jetson 上在线运行，配合基于运动的关键帧选择（每移动 0.5 m 处理一帧），在 3 个真实环境中恢复 44 个目标物体中的 35 个。
- **总体结论**：持久开放词汇 3D 场景地图可仅由单个 VLM 用轻量文本表示直接维护。

## 7. 优点

- **范式创新**：将场景地图维护（关联、纠错、删除）统一为单个 VLM 的自回归语言生成任务，用文本作为唯一持久记忆，去掉了专用几何后端与特征库。
- **表示紧凑**：内存占用比 FARM 小 6–12 倍，为长期、大规模部署提供轻量方案。
- **自动监督流水线 OVAL**：无需人工 3D 标注，可跨异构数据集扩展（1.3M 图像、10.7M 标注），并保留被拒标注作为 REMOVE 监督，设计巧妙。
- **训练任务设计细致**：
  - 逐物体独立腐蚀避免图像级相关性；
  - 扰动幅度不重叠以避免操作歧义；
  - 重新排序防止利用列表位置；
  - 部分上下文增强跨视图关联鲁棒性。
- **公平评测**：严格排除评测场景；对基线做多提示词对比；附录补充原 FARM 协议结果；对质量检查做了系统提示词消融并给出与人类判断的一致性分析（Cohen's κ）。
- **真实部署验证**：在四足机器人上验证了边缘端在线运行的可行性，并研究了量化与关键帧间距的权衡（约 0.5 m 最佳）。
- **诚实披露**：明确承认文本表示是有损的、推理延迟是主要瓶颈、真实场景中重复物体更多。

## 8. 不足与局限

- **推理成本高**：每处理一帧需完整自回归前向，约 900 ms/帧（A100），比 FARM 慢约 3 倍；在机器人上需依赖运动触发的关键帧选择（0.5 m/帧）才能避免积压，限制运行速度（2B NVFP4 约 0.44 m/s 名义速度）。
- **文本表示有损**：丢弃细粒度视觉信息，当多个实例标签/描述相似时产生歧义；不预测物体范围（extent），需外部尺寸估计器才能在 FARM 原 IoU 协议下评测，并引入额外误差。
- **模型容量未充分利用**：2B 模型检索表现优于 4B/8B，说明瓶颈在数据、建图形式或监督而非模型容量（但 8B 未使用短描述，比较不完全公平）。
- **单帧指标为下界**：因词汇表不完整、未解析拼写变体与同义词，Robj 等指标偏低。
- **评测协议差异**：主检索结果采用免范围"点入盒"协议，与 FARM 原 IoU 协议结论不完全一致（原协议下 FARM 在 R@5/R@10/MRR 上更好），可能影响与既有工作的直接可比性。
- **真实场景限制**：
  - 无实例级 3D 真值，评估依赖人工清单；
  - 办公室等重复物体场景中出现较多重复条目与语义模糊（如真皮扶手椅被描述为"深色椅子"）；
  - 户外场景因关键帧丢弃导致映射物体更少；
  - 行人运动易产生重复而非编辑。
- **失败模式**：物体误关联导致重复或多余编辑、误删有效物体（如保温杯、水瓶）、细粒度识别错误（飞镖盘被识别为挂钟）、运动模糊下产生重复。
- **动态与长期环境未覆盖**：作者自承未来工作需提升推理效率并扩展到更长时域和动态环境。
